# scoreboard

## 理論下限

### 1 ケースあたりの理論下限

- 最終長さを `k = M` にするには、少なくとも `M-5` 回の捕食が必要。
- 1 ターンで食べられる餌は高々 1 個なので、操作回数 `T` は少なくとも `M-5`。
- もし `k = M` かつ `E = 0` を達成できれば、絶対スコアは `T` だけになる。
- よって、各ケースの絶対スコアの理論下限は `M-5`。

### 生成範囲から見た下限の幅

- `M` は `ceil(N^2/4)` 以上 `floor(3N^2/4)` 以下。
- したがって理論下限 `M-5` は、全入力全体では `11` 以上 `187` 以下。
  - 最小: `N = 8`, `M = 16` のとき `M-5 = 11`
  - 最大: `N = 16`, `M = 192` のとき `M-5 = 187`

### 平均的な理論下限の目安

- 入力生成の平均でみると `E[M] ≒ 75.33`。
- したがって平均的な理論下限は `E[M-5] ≒ 70.33`。

## ランダム基準の見積もり

### 基準とするランダム解

- 「噛み切りなし」
- 「盤面をジグザグに全走査して全ての餌を食べる」
- このとき操作回数は常に `T = N^2 - 5`
- すべての餌を食べるので `k = M`

この基準は、移動は決め打ちだが、入力生成上は食べる色順が `d_5, ..., d_{M-1}` のランダム順列になる。

### 色不一致数の期待値

- 色ごとの個数を `m_c` とする。
- 固定された希望列に対して、ランダム順列を食べたときの一致数期待値は

```text
E[match] = (sum_c m_c^2) / (M-5)
```

- よって suffix の不一致数期待値は

```text
E[E_suffix] = (M-5) - (sum_c m_c^2) / (M-5)
```

- 初期 5 要素はすでに一致しているので、全体の不一致数期待値もこの値に等しい。

### バランスしているとみなした近似

- `m_c` がほぼ均等なら `sum_c m_c^2 / (M-5) ≒ (M-5)/C`
- このとき

```text
E[E] ≒ (M-5) * (1 - 1/C)
```

- `C = 3` なら不一致率は約 `2/3`
- `C = 5` なら不一致率は約 `4/5`
- `C = 7` なら不一致率は約 `6/7`

### 平均ケースの概算

- `E[N^2] ≒ 150.67`
- `E[M] ≒ 75.33`
- よって平均的なジグザグ全食べの操作回数は `E[T] ≒ 145.67`
- `C` を `3..7` 一様平均でみると `E[1 - 1/C] ≒ 0.7814`
- したがって、ランダム順ベースラインの不一致数は

```text
E[E] ≒ 54.96
```

- このとき絶対スコアはおおむね

```text
E[score] ≒ 145.67 + 10000 * 54.96 ≒ 549750
```

## スコア重みの読み方

- 不一致 `E` を 1 減らすと、絶対スコアは `10000` 改善する。
- 食べ残し `M-k` を 1 減らすと、絶対スコアは `20000` 改善する。
- したがって、少なくとも初期段階では `T` 短縮よりも `k = M` 達成と `E` 削減が重要。

## `M = k` 達成時の見え方

### スコア式の簡約

- `M = k` のとき、絶対スコアは

```text
score = T + 10000 * E
```

- つまり、この段階では `M-k` の重い罰は消え、勝負は `E` と `T` の 2 軸になる。

### 重みの差

- `E` を 1 減らす改善は `T` を `10000` 手縮める改善と同じ重みを持つ。
- したがって、`M = k` 到達後は `T` 短縮よりも `E` 削減を優先するのが自然。
- `M = k` に入った時点で、問題はほぼ「色順をどこまで正しくできるか」に移る。

### 目安

- `E = 0` なら、スコアはそのまま `T` になる。
- たとえば `T = 180`, `E = 40` なら

```text
score = 180 + 10000 * 40 = 400180
```

- たとえば `T = 500`, `E = 5` なら

```text
score = 500 + 10000 * 5 = 50500
```

- よって、多少遠回りでも `E` を数個減らせるなら十分に得になる。

### ランダム順に近い全食べとの比較

- 「全て食べたが色順はほぼランダム」という状態でも、`M = k` ならスコアはおおむね `T + 10000 * E` に収まる。
- 色がほぼ均等とみなせるとき、各 suffix 位置が一致する確率はおおむね `1/C` とみなせる。
- この近似では、不一致数期待値は

```text
E[E | M = k] ≒ (M-5)(1 - 1/C)
```

- よって、平均入力に対しては

```text
E[M-5] ≒ 70.33
E[1 - 1/C] ≒ 0.78143
E[E | M = k] ≒ 70.33 * 0.78143 ≒ 54.96
```

- したがって、`M = k` だが `E != 0` のランダム順ベースでは、色不一致ペナルティだけでおおむね

```text
10000 * E[E | M = k] ≒ 549600
```

- になる。
- 既存の平均ケース概算では、この状態の不一致数期待値は `E[E] ≒ 54.96`。
- したがって、`M = k` だが順序が悪い解の平均的なスコアはおおむね `50` 万点台になる。
- ここからの本質的な改善は、`T` よりもまず `E` をどこまで下げられるかで決まる。
