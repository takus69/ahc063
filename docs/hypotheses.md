# hypotheses

## 前提

- このファイルには仮説を書く。
- 問題の事実は `docs/problem.md` を参照する。
- ここに書く内容は、実験で否定・修正されうる。

## 問題構造の観察

- 絶対スコアは `T + 10000 * (E + 2(M-k))` なので、まず `M-k` と `E` を抑えることが主目標であり、`T` 短縮はその後段になりやすい。
- 初期状態では色列の先頭 5 要素が `1,1,1,1,1` であり、希望列も `d_0 = ... = d_4 = 1` なので、先頭 5 要素は最初から正しい。
- 入力生成上、初期配置される餌の色 multiset は `d_5, ..., d_{M-1}` のランダム順列である。したがって不足色の問題ではなく、順序をどう作るかが本質である。
- 噛み切りで切り落とした部分は餌に戻るため、色の総量は失われない。再捕食できれば `M = k` は理論上達成可能である。
- したがって、噛み切りは単なる失敗ではなく、suffix を作り直すための再構成操作として扱える可能性が高い。

## 重要な構造仮説

### 1. 先頭 5 要素は自動的に固定される

- 合法な噛み切りで残る長さの最小は 5 である。
- 頭は U ターン禁止により直後の胴体には進めず、1 手移動では 2 個先の胴体にも到達できないため、最も近く噛み切れる位置でも長さ 5 は残る。
- したがって、どのような噛み切りを行っても先頭 5 要素は常に保持される。
- 初期状態でその 5 要素はすでに正しいので、戦略上は `d_5, ..., d_{M-1}` をどう構成するかに集中してよい。

### 2. 本質は prefix 固定のまま suffix を再構成すること

- 噛み切りで保持されるのは head 側の prefix である。
- よって、正しい prefix をなるべく長く残しつつ、それ以降の suffix を食べ直す方針が自然である。
- この見方では、色一致問題は「正しい prefix を伸ばし続ける問題」に言い換えられる。

### 3. `M = k` と `E = 0` は十分に狙える目標である

- 噛み切りで長さは一時的に減るが、切り落とした部分は餌に戻るため、完走できれば `M = k` に戻せる。
- さらに、suffix を希望順どおりに組み直せれば `E = 0` も理論上可能である。
- そのため、まず `E = 0` に近い構成を作り、その後で `T` を削る二段構えが有望に見える。

## 有望そうなアルゴリズム仮説

### 1. prefix 固定・suffix 再構成 greedy

- 現在 `0..k'` が正しい prefix になっているとき、その先の構成が悪ければ噛み切って `k'+1` 以降を作り直す。
- 最も自然なのは「正しい prefix をできるだけ長く残して切る」方針である。
- まずは単純に、次に必要な色を作るために最短で噛み切り位置と再捕食順を決める greedy がベースラインになりうる。

### 2. 局所再構成を繰り返す hill climbing

- 一度全食べした解に対して、「どこで噛み切るか」「どの順で食べ直すか」を局所的に変えれば、suffix の順序を改善できる可能性がある。
- 特に、最初の不一致位置付近を対象にした局所再構成は効率が良いかもしれない。
- また、噛み切る直前に少し移動してから噛み切りに入ることで、再構成開始時の頭位置や向きが改善し、その後の再捕食がやりやすくなる可能性がある。
- したがって、局所改善では「噛み切り位置」だけでなく「噛み切り前の助走手順」も調整対象になりうる。

### 3. prefix 長を状態に持つ beam search

- 状態を「現在の正しい prefix 長」とみなすと、次にどの噛み切り・再捕食を行うかの探索問題として整理できる。
- 評価値は「prefix 長」「追加手数の見積もり」「再捕食の容易さ」を組み合わせる形が考えられる。
- まずは greedy で十分かを見て、難しいなら beam search に広げるのが自然である。

### 4. `E = 0` 構成を先に作ってから `T` を削る二段階法

- 問題の重み付け上、`E` や `M-k` の改善は `T` より圧倒的に大きい。
- したがって、まず長い prefix を維持しながら `E = 0` に近い構成を作り、その後に噛み切り位置や再捕食経路を短くする段階が有望に見える。

## 探索方法の候補

### 候補 A: 最長 prefix を残す噛み切り位置を選ぶ

- まず「どこまで正しい prefix を残せるか」を優先し、その位置で噛み切る。
- その後、必要な色順に suffix を食べ直す。
- もっとも単純で実装しやすい基準である。

### 候補 B: 盤面都合で少し手前から切る

- 最長 prefix を残したいが、その位置ではうまく噛み切れない場合があるかもしれない。
- その場合、少し頭側から切っても、胴体を食べ直すことで prefix を修復できる可能性がある。
- したがって、「最長 prefix 固定案」と「少し手前からの再修復案」の両方を比較する価値がある。

### 候補 C: 再捕食順の greedy

- 噛み切り後は、正しくしたい色順に従って、次に必要な色を最短で取りに行く。
- この段階ではまだ `T` 最適化よりも、正しく並べ直せることの確認を優先する。

### 候補 D: 差分改善

- すでに完成している解に対して、不一致が出る suffix だけを切って作り直す。
- 全体を作り直さず、必要な場所だけ局所修復できれば効率がよい。

## neighborhood 候補

- 噛み切り位置を 1 つ前後にずらす
- 最長 prefix を残す案と、1 つ手前から切る案を入れ替える
- 再捕食する suffix 区間の食べ順を swap する
- 再捕食する suffix 区間の連続区間を reverse する
- 再捕食する suffix 区間の一部を remove + insert する
- ある prefix 長で切って以降を greedy で再構築する
- すでに正しい prefix を維持したまま、不一致が出ている suffix だけを切り直す
- 噛み切り前に数手だけ移動してから切る助走手順を変更する
- 同じ prefix 長を残す噛み切りでも、再構成開始時の頭位置・向きが良くなるように切り方を変える

## スコア改善の方向性

### 1. まず `M = k` を維持できる再構成を作る

- 噛み切りを使っても、完走できれば `M = k` は達成可能である。
- 逆に、途中で止まると `M-k` のペナルティが非常に大きい。
- したがって、噛み切り戦略でもまずは「最後まで食べ切れる再構成」が必要である。

### 2. 先頭からの一致数を最大化する

- スコアは head 側から比較されるため、prefix を壊さずに一致数を増やすことが重要である。
- この点で、噛み切りを「prefix を保って suffix を作り直す操作」とみなすのは相性がよい。

### 3. `E = 0` に近づける価値は大きい

- `E` を 1 減らすだけで `10000` 改善する。
- したがって、多少 `T` が増えても、suffix 再構成で一致数を大きく伸ばせるなら得になりやすい。

### 4. `T` 短縮はその後

- `M = k` と高い prefix 一致が達成できた後で、ようやく `T` 短縮の比重が上がる。
- 初期段階では「正しい並びを作ること」を優先し、その後に移動や再捕食の無駄を削るのが自然である。
- ただし、噛み切り直前に少し移動してから入る助走は、その場では `T` を増やしても、再構成開始位置や向きを改善して全体の再捕食コストを下げる可能性がある。
- そのため、局所的な手数増加は直ちに悪とは限らず、「助走込みで suffix 再構成全体の手数と一致数がどう変わるか」で評価するのがよさそうである。

## 早めに確認したい仮説

- 合法な噛み切りで先頭 5 要素が常に残ることを小ケースで確認できるか。
- 最長 prefix を残して切る方針は実際に強いか。
- その位置で切れない場合、少し頭側から切っても再修復で十分回収できるか。
- 噛み切りあり戦略で `M = k` を安定して維持できるか。
- suffix 再構成により `E` を大きく下げられるか。
- `E` 改善量に対して `T` 増加がどの程度で済むか。
