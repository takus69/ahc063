# hypotheses

## 前提

- このファイルには仮説を書く。
- 事実は `docs/problem.md` を参照する。
- ここでの記述は、今後の実験で否定されうる。

## 問題構造の観察

- 絶対スコアは `T + 10000 * (E + 2(M-k))` なので、まず `M-k` と `E` を減らすことが主目標で、`T` 短縮はその次になりやすい。
- 初期状態で蛇の長さは 5、色はすべて 1 であり、希望色列も `d_0 = ... = d_4 = 1` なので、先頭 5 要素はすでに一致している。
- 初期配置の食べ物の個数は `M-5` 個であり、入力生成を見る限り、食べ物の色の multiset は `d_5, ..., d_{M-1}` のランダム順列になっている。
- そのため「必要な色が足りない」問題ではなく、「必要な順序で食べるのが難しい」問題だと考えられる。
- 自己衝突は即失敗ではなく、噛み切りによって蛇を短くしつつ食べ物を再配置できる。この操作が単なるペナルティではなく、順序調整のための能動的な手段になっている可能性がある。
- 尻尾だけは他部位と同じマスを共有できるため、通常の自己交差禁止パスとは少し構造が異なる。
- `T` の係数は 1 で、`E` と `M-k` の係数は 10000 オーダーなので、多少遠回りでも正しい色列を作る価値が高い可能性が高い。

## 有望そうなアルゴリズム仮説

### 1. greedy による色優先構築

- 「次に欲しい色 `d_k` を持つ食べ物のうち、近くて安全に取れるものを選ぶ」単純 greedy が強い初期解になりうる。
- 特に序盤は蛇が短く、移動自由度が高いので、色一致を優先した greedy が効きやすいかもしれない。

### 2. 色一致重視の beam search

- 直近数手ではなく、「次に食べる食べ物候補」を枝として持つ beam search が有望かもしれない。
- 評価値は `一致済み prefix 長`、`未達成色の残り個数`、`移動コスト見積もり`、`噛み切りの必要性` などの組合せが考えられる。
- 盤面サイズが最大 `16 x 16` と小さいため、短い horizon の探索は回せる可能性がある。

### 3. eat order を先に決めて経路を後から合わせる二段階法

- まず「どの色の食べ物をどの順に食べるか」を決め、その後に盤面上の移動列へ落とす二段階法が整理しやすいかもしれない。
- 色順の最適化と移動最適化を分けることで、探索空間を減らせる可能性がある。
- ただし蛇の形状制約と噛み切りの影響が強い場合、この分離は崩れる可能性がある。

### 4. 噛み切りを含む局所再構成

- 一度食べた順序が悪くても、噛み切りで末尾側を食べ物に戻せば、後半の色列を作り直せる可能性がある。
- そのため「前半 prefix を固定し、後半だけ再構成する」戦略が有効かもしれない。

### 5. 大域探索としての焼きなまし

- 初期解を greedy か beam search で作り、その後「食べる順序」「噛み切り位置」「再訪順」を焼きなましで改善する構成は自然に見える。
- 評価関数に絶対スコアそのものを使えるため、比較基準が明確である。

## 探索方法の候補

### 候補 A: 逐次 greedy

- 現在の蛇状態から、次に取る食べ物を 1 個ずつ決める。
- 近さだけでなく、食べた後の色一致と将来の詰まりにくさを評価に入れる。

### 候補 B: 食べる対象列に対する beam search

- 1 手ごとの移動ではなく、次に目指す食べ物単位で探索する。
- 各ノードで「その食べ物まで安全に行けるか」をサブルーチンで判定する形が考えられる。

### 候補 C: 局所探索

- 完成済みの解に対して、小さな食べる順の変更や噛み切り追加を試す。
- 差分評価が作れるなら反復改善しやすい。

### 候補 D: prefix 固定型探索

- 先頭から合っている prefix をなるべく壊さないように探索する。
- この問題では prefix の一致がそのまま `E` 減少に効くので、後半だけを動かす探索が安定するかもしれない。

## neighborhood 候補

- 次に食べる食べ物候補の変更
- 食べる食べ物 2 個の順序 swap
- 連続区間の reverse
- 連続区間の remove + insert
- 「この食べ物を取る前に 1 回噛み切る」を挿入
- 既存の噛み切り位置を前後にずらす
- ある prefix 長で打ち切って、以降を greedy で再構築
- 目標食べ物への到達経路だけを別経路に差し替える
- 一度食べた末尾区間を噛み切って取り直す

## スコア改善の方向性

### 1. まずは `k = M` を安定化する

- `M-k` には係数 2 が掛かり、さらに全体で 10000 倍されるため、食べ残しは非常に重い。
- まずは全食べ達成率を上げる方が、細かい手数短縮より効く可能性が高い。

### 2. prefix 一致数を増やす

- 色列は先頭から比較されるため、特に prefix を崩さずに一致数を増やす改善が重要そうに見える。
- 後半にミスを押し込む方が扱いやすい可能性がある。

### 3. `T` 短縮は二段目

- `E` や `M-k` が残っている段階では、数十手から数百手の短縮より、色一致の改善の方が効く可能性が高い。
- `k = M` かつ `E` がかなり小さくなってから、経路短縮の価値が上がると予想する。

### 4. 噛み切りは「避ける」より「使いどころを選ぶ」

- 噛み切りは長さ減少を伴うので無計画には弱そうだが、順序の修正や再配置に使えるなら有益かもしれない。
- 「噛み切り禁止」より、「prefix を維持したまま後半を作り直せる場面だけ使う」方が強い可能性がある。

- 噛み切りを使わない方針でどこまで戦えるか。

- 探索単位を「1 手」ではなく「次に食べる食べ物」にすると扱いやすくなるか。
